# Compression provenance

Every movie or episode a job finishes (it passed the output verification
and got its final name) records **which compressor version and settings
produced it, what happened to its tracks, and with which tools**:

- a compact set of `PROVENANCE_*` global Matroska tags inside the output;
- one record per output file in the provenance **manifest**
  (`~/compress/work/logs/provenance/manifest.json`).

Nothing about the encode changes: no extra encode or remux, the same CRF
decisions, stream selection and size checks. Tracking runs after the
verification and only writes tags (mkvpropedit) and log files. A failure
in tracking is a warning, never an item failure. Failed and interrupted
items record nothing.

## How it fits into a job

| Step (job_runtime.sh `item_succeeded`) | Provenance |
| --- | --- |
| job generated (`emit_job_header`) | `JOB_GIT_COMMIT` / `JOB_GIT_BRANCH` / `JOB_GIT_TREE` written into the job next to `JOB_COMPRESSER_VERSION`: the checkout state **when the job was created**, kept even if the checkout changes while it runs |
| every `item_run` | the executed ffmpeg argv is kept (`$ITEM_TMP/prov/cmd_<pass>`) |
| output verification (`hdr_dovi.sh item_verify_output`) | besides `report.txt`, one row per verified comparison in `$ITEM_TMP/ops.tsv` |
| after the verification passed | `item_provenance_tag`: new ID, `PROVENANCE_*` tags written into `<output>.part` |
| after the rename + statistics refresh | `item_provenance_record`: event (Git, tools, settings, ops, ffprobe of source and output) atomically moved into `logs/provenance/spool/`, then merged by `provenance.py ingest` |

Job scripts generated by an earlier version get the same tracking
(job_runtime.sh loads `provenance.sh` itself). They have no
`JOB_GIT_COMMIT`: their recorded `JOB_COMPRESSER_VERSION` (git describe)
is resolved to a commit when this checkout knows it
(`git.captured = resolved-from-describe`), otherwise the commit is
recorded as unknown. **The current HEAD is never substituted.**

When python3 is missing the event stays in the spool and the job says
so; `provenance.sh ingest` merges it later.

## What is recorded, and how it is known

Only values verified from the source, the output or the executed command
are recorded. Nothing is guessed from bit rates, file names or sizes.

| Field | Source |
| --- | --- |
| Git commit (full SHA), branch, dirty tree | `git` when the job was generated |
| date / time | UTC, ISO 8601, when the output passed verification |
| preset | the menu tier of the item (Quality / High / Base / Compact / Custom; `Audio <tiers>` for the audio menu) |
| tool versions | `ffmpeg`, `ffprobe`, `mkvtoolnix` as run by the job; `x265` from the settings SEI in the output stream; `dovi_tool` / `hdr10plus_tool` only when the item used them |
| CRF, planned CRF, CRF attempts | the job's final decision (`ITEM_EXP`), the attempts it made |
| x265 preset / tune / params / pixel format / scale filter | the executed ffmpeg command |
| actual x265 settings | the x265 settings SEI read back from the output |
| source and output properties | ffprobe of both files: codec, resolution, frame rate, bit depth, bit rate (`bit_rate_from`: stream or statistics tag), colour, HDR10 / HDR10+ / Dolby Vision (profile, compatibility id, EL), audio codec / channels / layout / rate / language / commentary, subtitle format / language / default / forced, chapter count + digest, attachments |
| operations (`changes`) | the verification rows, each `{scope, subject, action, detail, basis: "verified"}` |

Operation actions: `preserved`, `removed`, `converted`, `reencoded`,
`added`, `modified`. Scopes: `video`, `hdr`, `hdr10`, `dv`, `hdr10plus`,
`audio`, `commentary`, `subtitle`, `stream`, `attachments`, `chapters`,
`metadata`. Examples:

```
video      stream               reencoded  h264 yuv420p -> hevc 1920x800 yuv420p10le, CRF 21.0 (single pass)
video      resolution           modified   3840x1600 -> 1920x800 (downscaled)
dv         rpu                  converted  profile 7.6 -> 8.1 (RPU kept, verified)
dv         enhancement layer    removed    MEL discarded (single-layer output)
hdr10plus  dynamic metadata     preserved  re-inserted into the re-encode, verified
audio      track 3              converted  TrueHD (Atmos) 7.1 -> AC-3 5.1(side), lang eng
commentary track 2              preserved  lang eng, title Director Commentary, copied
subtitle   track 4              converted  mov_text -> subrip, lang eng
subtitle   subtitle 7 (dvb_subtitle)  removed  not supported in MKV
metadata   audio 1 title        modified   "TrueHD 7.1" -> "English | TrueHD | 7.1 | Atmos"
```

When the verification wrote no rows (an older verifier), `changes` is
empty and `changes_recorded` is `false`: per-track history is unknown,
not "unchanged".

## Embedded tags

Global tags (TargetTypeValue 50), written with `mkv_set_global_tags`
(encode_common.sh): every other global / track / chapter / attachment tag
is kept, the result is read back and the original tag set restored on
any difference. Chapters, attachments and streams are not touched.

| Tag | Value |
| --- | --- |
| `PROVENANCE_TOOL` | `movie-compresser` |
| `PROVENANCE_ID` | stable record ID (UUID v4) |
| `PROVENANCE_STATUS` | `recorded` (by the job); `recovered` / `unknown` (added later by `provenance.sh tag`) |
| `PROVENANCE_COMMIT` | full commit SHA, or `unknown` |
| `PROVENANCE_TREE` | `clean` / `dirty` / `unknown` |
| `PROVENANCE_TIME` | `2026-11-08T06:35:14Z` |
| `PROVENANCE_PRESET` | `High`, `Custom`, `Audio Compact`, ... |
| `PROVENANCE_OPS` | one-line summary of the verified operations, e.g. `video=reencoded x265 crf 21, 3840x2160->1920x1080; hdr=DV Profile 7.6 + HDR10 -> DV Profile 8.1 + HDR10; dv=profile 7.6 -> 8.1, EL (MEL) removed; audio=3 copied; commentary=1 kept; subs=4 kept, 1 converted` |
| `PROVENANCE_PARENT` | the ID of the source, when the source was itself a recorded output |

The tags describe the operation that **wrote this file**. The existing
`COMPRESSION_CRF` / `COMPRESSION_TIER` / `COMPRESSION_TOOL` /
`MOVIE_COMPRESSER_VERSION` / `COMPRESSION_DATE` tags are unchanged and
still describe the CRF encode of the video (they travel with a copied
video stream).

The tags are written after the last remux / chapter / cover step and are
left alone by everything that follows (statistics refresh, track-name
edits, verify.sh Validate + update). An ffmpeg remux with
`-map_metadata 0` keeps them; the compressor's own encode, stream-copy
and audio jobs drop the source's `PROVENANCE_*` tags in the mux and
write the new output's own (the source ID becomes `PROVENANCE_PARENT`),
so two files never claim the same ID.

## Manifest

`work/logs/provenance/` (override: `PROVENANCE_DIR`):

| File | Purpose |
| --- | --- |
| `manifest.json` | the records; replaced atomically (write temp, fsync, rename) |
| `manifest.json.bak` | the previous good manifest |
| `journal.jsonl` | every applied entry, append-only; the manifest is rebuilt from it when `manifest.json` and the backup are unreadable (`provenance.sh rebuild`) |
| `spool/<op>/` | job events not merged yet (event.tsv, ops.tsv, ffprobe JSON, executed argv) |
| `.lock/` | writer lock (several jobs can finish at once); removed when older than 10 minutes |

Schema (`"schema": "movie-compresser/provenance-manifest/1"`):

```jsonc
{
  "schema": "movie-compresser/provenance-manifest/1",
  "updated": "2026-11-08T06:35:15Z",
  "records": {
    "<id>": {
      "id": "<id>",                       // = PROVENANCE_ID in the file
      "kind": "movie" | "episode" | "unknown",
      "series": {"show": "Show", "episode": "S01E02"},      // episodes
      "status": "active" | "replaced",    // replaced: a later output took its path
      "replaced_by": "<id>", "replaced_at": "...",
      "provenance": "recorded" | "partial" | "recovered" | "unknown",
      "current": {"path", "name", "size", "segment_uid"},
      "locations": [{"path", "since", "reason": "created|moved|renamed|adopted|found by scan", "from"}],
      "lineage": {"parent_id", "parent_in_manifest", "source_path"},
      "tags_embedded": true,
      "original":   { /* operation that encoded the video (see below) */ },
      "operations": [ /* later operations, oldest first */ ]
    }
  }
}
```

Operation object:

```jsonc
{
  "op_id": "c3-20261108T063515Z-1-b116763f",
  "type": "compress" | "stream-copy" | "audio-compress" | "remux" | "provenance-tag" | "record-recovery",
  "time": "2026-11-08T06:35:14Z",
  "basis": "recorded by the job that produced the file",
  "job": {"session": "c3", "type": "movie", "item": 1, "log_dir": "..."},
  "preset": "Custom",
  "git": {"commit": "<sha>|null", "describe", "branch", "dirty": false, "captured": "job-generated|resolved-from-describe|unknown"},
  "tools": {"ffmpeg", "ffprobe", "mkvtoolnix", "x265", "dovi_tool", "hdr10plus_tool"},
  "settings": {"video", "crf", "crf_planned", "x265_preset", "x265_tune", "x265_params", "pix_fmt",
               "video_filter", "x265_settings", "x265_rate_control_in_stream", "scaled",
               "dolby_vision_policy", "dolby_vision_output", "hdr10plus_policy", "video_ceiling_bytes",
               "crf_range", "season_batch", "audio_transcode": [...], ...},
  "source": { /* compact media properties */ },
  "output": { /* compact media properties */ },
  "changes": [{"scope", "subject", "action", "detail", "basis": "verified"}],
  "changes_recorded": true,
  "crf_attempts": [{"crf", "estimated_video_bytes", "actual_video_bytes", "result", "reason"}],
  "verification": "passed",
  "embedded_tags": {"state": "written | failed:<why> | skipped:<why>", "ops_summary": "..."}
}
```

Rules:

- **One record per output file**, keyed by the ID embedded in it.
- **Re-encoding** (`compress`) starts a new history: `original` is that
  encode; `lineage.parent_id` points to the source's record.
- **A copied video** (stream copy, audio menu): `original` is the
  parent's original encode (with `inherited_from`), `operations` the
  parent's operations plus the new one. Without a parent record the
  original is `{"status": "unknown"}` and `provenance` is `partial`.
- **Processing again into the same path**: the earlier record stays,
  marked `replaced` with `replaced_by`; history is never deleted.
- **No duplicates**: an event already applied (same ID / op_id) is
  skipped; replaying the journal gives the same manifest.
- **Moved / renamed files** keep their ID tag; `provenance.sh relink`
  records the new location (old ones stay in `locations`). Files whose
  ID tag is missing are matched by Matroska segment UID + size.

## Commands (`provenance.sh` in the project root; python 3.6+)

```
provenance.sh scan    [PATH...] [--json]     # read-only; default ~/compress/out
provenance.sh tag     PATH... [--dry-run]    # explicit files only
provenance.sh relink  [PATH...] [--dry-run]
provenance.sh compare [PATH...] [--json]     # read-only
provenance.sh show    ID|FILE
provenance.sh ingest
provenance.sh rebuild [--dry-run]
```

**scan** reports, per MKV: embedded provenance, the matching record, the
current media properties, and for files without provenance what can be
recovered from

- the `COMPRESSION_*` tags earlier versions wrote (CRF, tier, date, Git
  describe; the describe is resolved to a commit when this checkout has
  it),
- `work/logs/compression_tags.tsv` (the CRF ledger: same path, else same
  file name; disagreeing rows are ignored),

listing every value with its source under *Known* and the rest under
*Unknown*. Records whose file is gone are listed too. Nothing is written.

**tag** gives files without provenance a `PROVENANCE_ID` (tags only:
streams, chapters and attachments unchanged) and a record with
`provenance` `recovered` (some values from logs / legacy tags) or
`unknown`. It never claims the current commit produced the file: the
tagging is recorded as a `provenance-tag` operation whose `git` is the
checkout that added the tag. `--dry-run` shows the tags that would be
written. Only files named on the command line are touched.

**relink** records moved / renamed files and recreates records lost from
the manifest from the embedded tags (`record-recovery`, marked as such).
Two files carrying the same ID are reported, not relinked.

**compare** classifies every active record (or the named files) against
the current checkout:

| Class | Meaning |
| --- | --- |
| Current | processed by the current commit |
| Older version, no relevant processing changes | older commit; nothing relevant to this file changed since |
| Potentially affected | encoder / HDR / audio / subtitle logic relevant to this file changed since (the files and functions are listed) |
| Manual review | the impact cannot be determined: commit not in this repository, dirty tree at processing time, changes in code the classifier does not know |
| Unknown provenance | no record, or the original encode was not recorded |

How changes are judged: `git diff <recorded commit> HEAD` hunk by hunk;
each hunk is attributed to the shell function it is in and mapped to an
area (table in `provenance.py`: `FILE_AREAS`, `FUNC_AREAS`).
Comment-only hunks, tests, documentation, UI / reporting / orchestration
code are ignored. HDR / Dolby Vision changes count only for files whose
source had HDR10 / HLG / HDR10+ / DV; subtitle changes only when there
were subtitles; audio-menu changes only for files an audio job produced;
`movie_compress.sh` / `series_compress.sh` only for movies / episodes.
Title, tag, chapter-restore and verification-only changes are listed as
notes (they never need a re-encode; verify.sh Validate + update refreshes
titles). Nothing is ever re-encoded, and an older commit alone is never a
reason to re-encode.

## Limitations

- The checkout's state is taken when the job is generated; uncommitted
  changes are recorded only as `dirty` (the diff itself is not stored),
  so such files always go to manual review.
- The change classifier works per shell function via Git's hunk headers;
  a change in an unmapped place is reported as "manual review" rather
  than guessed. Changes in `compress.conf` are judged by the variable
  names on the changed lines.
- Files processed before this feature have only what their legacy tags
  and the CRF ledger say; everything else is reported as unknown.
- A job killed after the tags were written but before the rename may
  leave a completed CRF attempt (`*.accepted-crf*.part`) carrying an ID
  without a record; `scan` reports it as "embedded-only".
- HDR10+ presence is per frame: the record shows it as verified by the
  job (frame probe), not from ffprobe's stream summary.
